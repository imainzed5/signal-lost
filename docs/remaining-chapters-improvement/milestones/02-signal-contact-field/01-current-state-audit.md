# 01 - Current-State Audit

## Dependency baseline

This milestone begins only after Milestone 01 resolves the current lint, cleanup, resize, input-semantic, and compact/short blockers. Re-run its command and route checks before design edits.

## Current player flow

1. SIGNAL title/sidebar and all three bright clusters appear immediately.
2. Pointer approaches any cluster.
3. Proximity accumulates stability; leaving decays it.
4. Stabilized cluster becomes the route target.
5. Pointer moves toward the central carrier; entering center routes the cluster.
6. All three route -> convergence effect -> route completion -> staged choice overlay.
7. Choice is saved; replay or Chapter 3 continuation becomes available.

## Current data and visual assets

- `signals.ts` defines three identities, normalized positions, radii, color, cue, and three short lines.
- Canvas contains 180 particles, 25 interference particles, contact glows, refraction bands, curved threads, carrier pulses, scan lines, and a completion shockwave.
- CSS contains full-height sidebar, directive, choice surface, compact stacking, and reduced-motion animation overrides.
- `sceneChoice` already carries saved value, confirm, replay, and continuation.

## What is worth preserving

- Raw Canvas ownership and layered depth ambition.
- Amber/cyan/violet contact palette.
- Carrier, host pressure, and retained route concepts.
- Continuous forgiving stabilization and routing.
- Explicit preview/commit persistence bridge.

## Design gaps

- Contacts are objectives before they are presences.
- Interaction is mechanically identical across all three.
- Story meaning sits in a dense instrument sidebar.
- Host pressure is mostly a metric and particles, not spatial pursuit.
- Contact does not accumulate a readable history beyond routed status.
- Ghost is a violet target rather than discovered negative space.
- Choice is a conventional panel rather than a carrier transformation.
- No canonical branch-specific aftermath plays inside the field.

## Baseline viewport evidence

- 1440x900: large title dominates left, full telemetry sidebar occupies 280px, quiet Canvas area is visually subordinate in the available static capture.
- 390x844: 1234px page; directive overlaps transit queue rows.
- 1280x640: sidebar content exceeds clipped fixed height by 250px.
- Renderer interaction was not live-verifiable in the planning browser and must be captured before edits in the implementation environment.

## State/timing risks

- Randomized geometry makes before/after comparison difficult unless the milestone introduces a stable seed.
- Multiple contact and UI states can diverge if Canvas and React own the same transition.
- A saved current-chapter stance must not skip the authored scene on replay.
- KEEP/DECAY texture must remain neutral when the choice is missing.
- Completion and choice confirmation must remain distinct.

## Accessibility risks

- Essential dialogue drawn in Canvas needs semantic equivalent.
- Keyboard focus and touch finger occlusion need encounter-specific design.
- Ghost discovery cannot depend on motion or violet alone.
- Assistance copy must not shame or create a failure label.

## Performance/cleanup risks

- Large chapter file and random allocations can hide per-frame work.
- Responsive rebuild can erase retained traces if geometry/state are not separated.
- React must update only at semantic boundaries/bounded status cadence.
- Replay must clear sequence, input capture, RAF, timers, and choice preview.

## Baseline failures versus regressions

Any unresolved Milestone 01 row remains baseline and blocks this milestone from starting. Once Milestone 02 starts, losing current completion, persistence, route continuation, build/lint health, or a previously passing input/viewport is a regression.
